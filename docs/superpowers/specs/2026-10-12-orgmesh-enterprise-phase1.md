OrgMesh Go 企业功能第一期设计
评审稿 2026年10月12日

本稿用于确认第一期交付边界和接口方案。目标是逐步建立 OrgMesh 自有企业业务能力，同时保持现有网页和 AI 主流程稳定。用户已选择 Go；本次只交付设计，尚未编写产品代码、实施计划或提交 Git。

一 目标与范围

第一期交付三个小闭环：
1. 品牌配置：管理员修改名称、欢迎语和已审核 Logo 资源引用；网页读取并展示。默认沿用已确认的 OrgMesh 标识。
2. 审计记录：可靠记录新服务已提交的品牌配置变更，并提供管理员查询。管理读取及拒绝或失败尝试仅作尽力记录的结构化日志；明确标示采集范围，不能冒称全站操作审计。
3. 用量统计：按日期、模型和流程展示 Token 与来源可解释的估算费用，区分用户用量与系统用量，显示更新时间。

第一期不做：硬配额拦截、付费订阅、用户组权限替换、SCIM、外部系统权限同步、全站历史日志迁移、任意分析脚本、自定义 HTML、Logo 上传服务、多租户自助开户。现有品牌补丁是独立交付，不视为本期代码。

建议默认：先服务现有单组织部署；数据结构始终带组织标识；仅现有经过验证的全局管理员可管理本期功能；不增加新角色、长期凭据或外部服务接入。

二 服务边界

保留 Next.js/React 网页和 Python/FastAPI 的登录、AI 调用、检索、连接器及现有数据写入。在它们旁边增加一个 Go 模块化服务 orgmesh-enterprise，内部划分品牌、审计、统计三个模块，先一个部署单元，不拆成多个微服务。

网页仍调用同源 Python API 适配层，避免浏览器直接持有服务凭据。适配层完成当前会话、当前权限和组织校验，再调用 Go；Go 再校验可信调用方与请求上下文。两端之间使用版本化 HTTP/JSON 契约，可采用受保护的本机套接字或已有已授权的服务认证通道。实际通道要在可用开发环境确认；不能以裸露 TCP 加自报身份请求头代替认证。

新增 Go 服务和 Python 适配层只增加必需接点，不重写身份登录、AI 管线或整个前端。数据库可复用 PostgreSQL 实例，但数据所有权分开。现有 Go 历史服务不直接扩展成全部企业平台。

三 第一批接口

下列是拟定的新契约，不是已经存在或上线的接口。公开路径统一位于 /api/orgmesh-enterprise/v1。

- GET /branding：返回当前组织的展示配置及版本；只含可公开展示的白名单字段。登录前页面的组织只能由服务器可信域名映射或单组织固定配置确定。
- PATCH /branding：修改白名单配置，要求管理员权限和 expected_version；版本冲突返回 409，不覆盖他人的修改。无任意 HTML、脚本和任意外链拉取。
- GET /audit/events：管理员分页查询本期审计记录，可按时间、操作、结果筛选；稳定游标，限制时间范围和每页条数。
- GET /usage/summary：管理员查询有限日期范围内的用户和系统汇总；返回统计窗口、来源、最后同步时间及是否陈旧。第一期不提供原始聊天内容和明细导出。
- 内部 usage-snapshots 写入契约：仅可信 Python 适配器可调用，浏览器不可访问。使用版本号和稳定记录键接收聚合快照，不是累加事件。
- 健康检查只给运行状态，不公开身份、数据库配置或凭据。

管理操作须同时经过会话鉴权、权限检查和资源组织检查。相同 request_id 的重试必须返回原结果或冲突，不能重复生成变更。

四 数据所有权与统计口径

Go 独占维护新命名空间 orgmesh_enterprise 中的品牌配置、审计记录、用量快照和同步游标；其表迁移也仅由 Go 服务负责。所有业务主键、唯一键和查询条件包含 tenant_id。Python 保持原有用户、会话、AI 用量与业务表的唯一写入责任；不允许 Go 直接修改它们。

品牌配置保存版本号、更新时间与操作者。成功的品牌配置创建或修改与对应审计记录在同一个数据库事务提交；审计落库失败时该配置变更回滚。审计查询页只承诺展示这些持久化变更。审计或用量读取、被拒绝及失败的请求输出脱敏结构化日志，不承诺其事务级完整性。审计应用接口只追加，不提供编辑删除；这不等于防篡改合规存证。记录 actor_id、tenant_id、action、resource_id、result、request_id、发生时间和最少必要的变更摘要，不保存密码、令牌、聊天正文或完整凭据。

已核对的社区审计模块目前是结构化日志输出，不能直接当成事务级可靠事件队列。第一期不修改登录失败行为来等待审计服务，也不承诺捕获全部旧日志。以后扩展到 Python 业务变更时，应由该业务写入方在同一事务写入其自有 outbox，再可靠投递；不能靠报表抓取倒推审计事件。

已核对的社区用户用量数据是可变的窗口聚合，不是每次调用的追加账本。Python 适配器每分钟读取已提交的用户及系统用量，生成有版本的窗口快照。稳定键包括组织、来源、用户或系统归属、窗口、模型、流程、提供方及隐私标记；Go 采用幂等覆盖而非重复相加。更正、清零和删除通过显式替换标记处理，不把“未读到”当删除。游标与写入原子提交，失败保留上次成功值，允许重试。

时间按 UTC 窗口聚合，界面可转换显示时区；用户与系统金额先分开展示，未确认无重叠前不相加。金额保留来源精度与货币单位，标注估算；未知价格不是零费用，货币单位未确认就不展示金额。既有隐私/无痕规则不得因报表而放宽。统计从启用后的首个来源窗口边界开始，跨越启用时刻的旧窗口不计入新汇总；页面显示实际统计起点，等待期间显示尚无符合条件的窗口。不能从聚合快照推算精确的启用后增量；历史回填另评审。健康条件下，两分钟内可看到下一次符合条件的快照；过期时显示陈旧状态，不伪装为零。

五 安全与故障行为

身份与 tenant_id 不接受浏览器任意指定。可信上下文包含当前用户、组织、允许的操作、受众、短期有效期和 request_id；若采用签名令牌，必须校验签发方、受众、有效期，并防止跨服务重放。没有合法会话、可信通道、组织映射或授权结果时拒绝管理请求，不能退回管理员身份或默认组织。

第一期不更换现有登录方式，不自行签发管理员长期 Token。若后续选型需要生成新凭据、创建服务账号或改变安全配置，实施前逐项请求对应授权；本稿不授权这些动作。

Go 不可用时：品牌读取使用启用前已确认的本地静态品牌配置，无自定义时采用 OrgMesh 默认展示，不读取其他组织的缓存；管理写入和审计查询返回明确不可用。统计页面仅可保留当前会话已取得的同组织结果并显示时间，切换用户或组织即清空；没有已取得结果则显示不可用，不新增第二套持久缓存。普通 AI/聊天流程不依赖这三个新模块继续可用。新模块关闭时不得自动跳转到未授权的企业实现。

六 迁移与回退

使用三个独立且默认关闭的功能开关：品牌、审计页面、用量页面。实际名称在实施计划确定，属于新开关，不复用或改变旧授权开关的含义。

迁移只新增表，不删除、重命名或改写原业务表。先在隔离测试环境建表和验证契约，再选择一个测试组织启用；真实环境启用与部署另行确认。已有品牌自定义值不自动覆盖，首次迁移需预览并确认字段映射；无迁移值时使用静态默认配置。

回退时关闭新路由与页面，保留新表和审计记录，恢复启用前已确认并留存的静态品牌配置，停止新统计采集，不回调旧企业配置服务。重开后按游标和快照版本恢复，验证没有重复统计。第一期不实施自动数据删除；正式使用前由用户确认留存、备份与访问策略。

七 验收要求

- 品牌：授权管理员修改后页面生效；同一版本并发编辑只能一个成功；配置与审计同进同退；静态回退可用。
- 权限：未登录、普通成员、过期或伪造服务上下文均被拒绝；组织 A 不能通过修改参数、游标或资源 ID 访问组织 B。测试环境至少建立两个组织样本。
- 审计：成功的品牌配置创建和修改均有事务内记录；可按 request_id 追踪；重试不重复；记录不含密钥或聊天正文。读取、拒绝及失败日志的尽力记录边界在页面说明，不声称全覆盖。
- 统计：同一快照提交多次不增加用量；乱序、清零、更正、断点重试和时区边界都有测试；用户/系统分离且缺失价格可见；与 Python 来源样本在同窗口、单位和精度下对账一致。
- 故障：Go 或数据库不可用时管理操作拒绝、品牌安全回退、统计提示陈旧，聊天回归测试通过。
- 集成：现有自定义品牌、登录、聊天、检索不回退；开关可单独关闭；新增前后端通过单元、契约、集成和浏览器测试，并记录实际未通过或未运行项。
- 依赖：新增实现、构建路径和运行时调用不偷偷进入受单独许可约束的企业实现；复用的社区代码保留其必需声明。此项需做依赖核对，不能只检查目录名。

八 后续阶段

第二期：在身份和资源授权模型验证后，独立实现用户组、组级管理权限、预算统计及告警；硬预算另定义原子预占、结算、取消退款和幂等行为，再切入真实请求链路。

第三期：SCIM 和外部权限同步，再按需要补充 Hooks、标准答案、增强搜索及模型网关等。先确认停用账号、权限撤销时效、失败时拒绝策略和定期对账规则。多租户运营、付费和计费系统须单独评审，不默认全部纳入首轮重建。

九 进入实施计划前确认

请用户确认：同意“单组织先用、管理员专用、品牌配置加本期审计和用量统计、暂不做硬配额”的第一期范围。若目前最需要的是用户组或配额而非这三个模块，请先调整优先级。

拿到可用开发环境后核实：最新分支及未提交变更；真实运行是否加载企业模块；社区登录和权限适配点；租户如何确定；用户/系统用量隐私与币种口径；可复用的内部认证通道；部署拓扑、留存策略和回退入口。发现与本稿不符时先修订设计，不暗中扩大范围。

本稿批准后再编写可执行实施计划，届时单独确定执行方式。当前未提交设计到 Git；待有合适、已授权的检出后再处理。未获得部署、推送、新凭据或安全配置变更授权。
